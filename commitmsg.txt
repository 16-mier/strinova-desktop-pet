修用户实测5问题 + 数据目录统一到桌面

用户反馈: 右键没有任何选项了 / 三横跟随延迟很高 / 没有动作 /
          拖动没有任何反应很生硬 / 鼠标移入没有显示输入栏了

① 右键菜单空白(严重)
  根因: _build_3d_menu 用 _mate3d_sections() 从 _build_mate3d_menu() 的
        返回值抽子菜单, 但那个 full 是局部变量, 函数返回后被 Python GC
        回收, 挂在它上面的子菜单一起失效 -> 实测报
        RuntimeError: wrapped C/C++ object of type QMenu has been deleted,
        菜单渲染成空白
  修复: 改为自建全部子菜单(_fill_3d_*_menu), 并把子菜单存 self._xxx_sub
        防 GC; 彻底删掉 _mate3d_sections

② 三横浮层跟随延迟
  根因: 轮询定时器 400ms, 拖 3D 窗口后三横要过 0.4 秒才挪
  修复: 降到 33ms; 另在拖动时通过 win.overlay_sync 回调即时同步

③ 没有动作
  根因: 待机动画幅度只有 0.004m(4毫米)且只是整体平移, 肉眼看不出
  修复: 放大到呼吸 ±1.2cm(周期3.1s) + 摇摆 ±1.2° + 手臂轻摆 ±3.5°
        + 每 7 秒歪头一次(平滑淡入淡出); relaxArms 记录 armBase 作摆动基准

④ 拖动没反应、很生硬
  根因(两层): ① 只重写 QWidget.mousePressEvent, 但窗口铺满
        QWebEngineView, 鼠标事件全被 web 视图吃掉, 传不到 QWidget
        ② JS 侧 pyBridge.dragWindow 和 Python 侧同时在搬窗口, 两套打架
  修复: Python 侧装 eventFilter(装在 view 上)统一接管拖动, 按屏幕坐标
        增量移动 + 屏幕内夹紧; 关掉 JS 侧拖动(只保留视线跟随)

⑤ 鼠标移入不显示输入栏(两个根因)
  根因A: 3D 模式下 2D 桌宠窗口是隐藏的, 而输入栏展开靠
        PetWindow.enterEvent 触发 -> 永远不触发
        修复: Web3DPetWindow 新增 hoverChanged 信号, 在 eventFilter 里
              检测进出并转发给 pet._on_web3d_hover
  根因B: 输入栏位置用 self._pet.frameGeometry() 算, 3D 下 2D 窗口隐藏
        -> 位置无效(跑到屏幕别处)
        修复: 新增 _GeoProxy 几何代理 + _set_geo_anchor(), 进 3D 时把
              ai._pet / chat._pet 的锚点永久换成 3D 窗口, 退回 2D 还原
        ⚠ 不能用临时替换: 输入栏跟随靠定时器每 100ms 跑 _follow_pet(),
          临时替换在调用瞬间有效、定时器跑时补丁已还原 -> 位置纹丝不动
          另换锚点必须清 _follow_offset(缓存了相对旧锚点的偏移)
  另: 原来要求 ai.enabled() 才弹输入栏, 现改为 AI 未启用也弹(给反馈)

⑥ 数据目录统一到桌面(避免两份数据打架)
  背景: 以前源码运行读脚本目录、打包运行读 exe目录/卡丘简易桌宠数据,
        两份并存 -> 用户改一份程序读另一份
  修复: base_dir() 统一 —— 源码运行也优先用桌面「卡丘简易桌宠数据」
        (该目录存在时); 支持 PET_DATA_DIR 环境变量显式指定
  _seed_default_assets() 改为源码运行也执行: 首次运行把内置 assets
        (24 角色立绘/人设/世界书/语音)播种到桌面, 已存在的不覆盖
  数据迁移以桌面版为基准合并配置: 保住 AI 配置 22 个子键
