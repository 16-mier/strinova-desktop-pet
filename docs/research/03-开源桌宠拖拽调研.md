# 开源 3D 桌宠「拖拽交互」调研报告

> 目标环境：Win11 + PyQt6 + QtWebEngine(Chromium) + three.js + @pixiv/three-vrm，米雪儿 VRM 1.0（原生 springBone + 42 表情），120fps 帧循环，全局鼠标轮询。
> 痛点：拖腰时像木偶（只有平移/倾斜/腿摆两下）。
>
> **证据标注**：`【自查】`＝本报告作者直连源码逐行核对原文；`【子代理】`＝子代理抓取并核验，作者未二次复核。所有链接均可复查。

---

## 一、结论先行

**1. 没有现成项目能直接抄。** 在全网主流开源 3D/VRM 桌宠里，**没有任何一个实现了"鼠标按住在角色身上拖动角色本体"**。ClawBody、claw-sama、VPet、openpets 拖拽时移动的都是**操作系统窗口**（`startDragging()` / `MoveWindows()` / `setBounds()`），VRM 在 3D 世界里的坐标**根本没变**——所以它们的 springBone 察觉不到位移，头发裙摆永远不会被甩动。这恰好解释了为什么这类项目拖起来都"很木"。

**2. "木偶感"的根因是直接赋值位置。** 反例最典型：joker20020/DesktopPet 用 `transform.position = 鼠标位置` 硬赋且**没有 Rigidbody2D**【子代理】。凡是把角色位置直接等于鼠标位置的做法，都必然像木偶。

**3. 真正的解法分成三件互不冲突的事，开源项目分别只做对了一件：**
- **抓取点/吊点（grab point）** → VPet 做对了（`RaisePoint` + `Raised_Dynamic`/`Raised_Static` 四阶段状态机）
- **弹簧力跟随而非位置赋值** → GodotDesktopPet 做对了（`F = kx − cv`，k=80, c=6，拖拽时重力降到 0.1 倍）
- **拖拽位移真正进入 3D 世界 + 松手速度继承** → **无人实现**，需要自己写（Shimeji 的 `Thrown` 是 2D 里唯一做对的）

**4. 对我们最重要的一条技术结论**：要让头发/裙摆因惯性甩动，**必须真的移动 `vrm.scene` / hips 骨骼**，而不能只搬 Qt 窗口。同时**必须给 springBone 设 `center`（骨盆）**，否则移动人形时全身 springBone 会集体甩飞【子代理，vrm-specification】。

**5. 阈值可直接抄的实测值**：4px（openpets）/ 5px+300ms（claw-sama）/ 8px（airi）/ 12px+250ms（GodotDesktopPet）/ 20px（VPet）。

### ① VPet ⭐6781 —— 唯一有正经「吊点模型」的项目

- 链接：https://github.com/LorisYounger/VPet
- 定位：最知名的开源桌宠模拟器，可内嵌进任何 WPF 应用。

**"被提起来"的四阶段状态机（最值得抄的设计）** —— 枚举里直接写着"被提起动态/静态"【自查】：

```csharp

```
状态机【自查】（`MainDisplay.cs:373-417`）：
- `rasetype 0,1,2` → 连播 **`Raised_Dynamic`（Single）**：被提起瞬间的**动态挣扎/悬垂**帧，播 3 次
- `rasetype 3` → **`Raised_Static` 的 `A_Start`**：进入稳定悬吊姿势
- `rasetype 4` → **`B_Loop`**：**保持被抓时的循环悬吊动画**（一直播到松手）
- 松手时 `rasetype = -1` → **`C_End`** → 回 `DisplayToNomal()`

**松手**：无重力、无甩出；仅可选 `SmartMoveTimer`（周期 1.2s）走回原位。

> **可借鉴点**：`RaisePoint`（吊点随状态变化）+ `Raised_Dynamic`(3次) → `A_Start` → `B_Loop`(held) → `C_End`(release) 这套四段式，是**不依赖任何物理引擎**就能让"被提起来"有起承转合的设计。我们可以把 `Raised_Dynamic` 映射成骨骼抖动+腿摆动，`B_Loop` 映射成 springBone gravityPower 调高的持续悬垂。

### ② GodotDesktopPet（NightMin2002）—— 物理最完整，「弹簧力」范式的唯一完整实现

- 链接：https://github.com/NightMin2002/GodotDesktopPet
- 定位：赛博机械单眼桌宠，纯代码渲染零贴图，在窗口间跳跃/奔跑/滚动，遵守重力碰撞弹性。
- 技术栈：Godot 4.6 .NET。`RigidBody2D` + `CircleShape2D r=30`，`mass=2.0`，`linear_damp=0.5`，`CCD_MODE_CAST_RAY`【子代理】。

**拖拽：不关物理，改用弹簧力牵引（这是治木偶感的关键）**【自查，`entities/pet/states/drag.gd` 全文 67 行】：

```gdscript
const SPRING_STIFFNESS := 80.0   # 弹簧刚度 (越大跟随越紧)
const SPRING_DAMPING := 6.0      # 阻尼系数 (越大振荡越少)
const DRAG_GRAVITY_SCALE := 0.1  # 拖拽时降低重力

func enter() -> void:
    original_gravity_scale = pet.gravity_scale
    pet.gravity_scale = DRAG_GRAVITY_SCALE   # 100% → 10%
    pet.linear_damp = 0.5
    pet.movement.cancel()                     # 被抓住时取消移动方向
    _init_mouse_pos = pet.get_global_mouse_position()
    _init_pet_pos = pet.global_position
    EventBus.drag_started.emit()

func physics_process(_delta: float) -> void:
    var mouse_pos = pet.get_global_mouse_position()
    var displacement = mouse_pos - pet.global_position
    # 弹簧力: F = k * x - c * v
    var spring_force  = displacement * SPRING_STIFFNESS
    var damping_force = -pet.linear_velocity * SPRING_DAMPING
    pet.apply_central_force(spring_force + damping_force)   # ← 施力，不是赋位置
```

**拖拽 vs 点击判定（0.25s / 12px）**【自查】：
```gdscript
# drag.gd:56-64
func input(event: InputEvent) -> void:
    if event is InputEventMouseButton:
        if event.button_index == MOUSE_BUTTON_LEFT and not event.pressed:
            var dist = pet.get_global_mouse_position().distance_to(_init_mouse_pos)
            if _drag_time <= 0.25 and dist < 12.0:
                _handle_poke()              # 算"戳一戳"
            pet.transition_to("fall")        # 松手 → 自由落体
```

**松手后**：`transition_to("fall")` 恢复 `gravity_scale=1.0`，**不清零速度**（惯性来自弹簧残余速度，无额外抛掷冲量）；落稳判定 `SETTLE_THRESHOLD=15.0` 速度持续 `SETTLE_TIME=0.3` 秒【自查，`fall.gd`】。

**形变补重量感**：`pet_squash.gd` 三档 Squash&Stretch，冲量 `v₀ = target_deform × √stiffness`；速度拉伸阈值 speed>60，`(speed-60)/1200`【子代理】。

**Windows 穿透（与我们处境完全相同）**【自查，`core/hit_region_manager.gd` 全文 349 行】——双模式：
```gdscript
# 模式A (完美): WS_EX_LAYERED 注入成功 → 本地命中检测 + WS_EX_TRANSPARENT 切换 → 零裁剪
# 模式B (回退): 注入失败 → SetWindowRgn AABB 矩形区域 → 特效区域有裁剪
func _update_click_through() -> void:
    var screen_pos = DisplayServer.mouse_get_position()   # ← 全局鼠标位置轮询
    var win_pos = get_window().position
    var mx = float(screen_pos.x - win_pos.x)
    var my = float(screen_pos.y - win_pos.y)
    var hit = _point_in_any_region(mx, my)                # 圆 + AABB
    if hit and _is_click_through:      _set_click_through(false)
    elif not hit and not _is_click_through: _set_click_through(true)

func _point_in_any_region(mx: float, my: float) -> bool:
    # 精确命中检测: 圆形 (dx²+dy²≤r²) + 矩形 (AABB)
    if (mx-cx)*(mx-cx) + (my-cy)*(my-cy) <= r*r: return true
```
- **限流**：`COLLECT_INTERVAL := 0.008  # ~120fps`（收集命中区域）
- **拖拽期间强制可点击**：`if is_dragging or is_menu_open: _set_click_through(false); return`
- **`WS_EX_TRANSPARENT` 只在进出边界时切换一次**（不是每帧 `SetWindowLong`）
- 回退模式做**栅格量化** `_q(v) = int(v/4.0)*4.0` 抑制 `SetWindowRgn` 抖动

> **可借鉴点**：`F = kx − cv` + 拖拽时重力降到 0.1 倍，是"拎起来"手感的最小完整内核。以及**拖拽期间强制关闭穿透**这条铁律——丢鼠标事件会让拖拽断线。

**身体部位识别：Raycaster 打真网格 → 找世界坐标最近的骨骼**【自查，`VRMScene.tsx:505-553`】——这个手法比纯包围盒贴模型：
```ts
const boneRegionMap: [string, TouchRegion][] = [
  ['head','head'], ['neck','head'], ['leftEye','head'], ['rightEye','head'], ['jaw','head'],
  ['leftShoulder','arm'], ['leftUpperArm','arm'], ['leftLowerArm','arm'], ['leftHand','arm'],
  ['rightShoulder','arm'], ... ['leftUpperLeg','leg'], ['leftLowerLeg','leg'], ['leftFoot','leg'], ...
  ['chest','chest'], ['upperChest','chest'], ['spine','belly'], ['hips','buttocks'],
]
function detectTouchRegion(e: PointerEvent): TouchRegion | null {
  touchMouseVec.set((e.clientX/window.innerWidth)*2-1, -(e.clientY/window.innerHeight)*2+1)
  touchRaycaster.setFromCamera(touchMouseVec, camera)
  const intersects = touchRaycaster.intersectObject(vrm.scene, true)   // ← 打真实网格
  if (intersects.length === 0) return null
  const hitPoint = intersects[0].point
  let closestRegion: TouchRegion = 'belly'; let closestDist = Infinity
  for (const [boneName, region] of boneRegionMap) {
    const bone = vrm.humanoid.getNormalizedBoneNode(boneName as any); if (!bone) continue
    bone.getWorldPosition(_bonePos)
    const dist = hitPoint.distanceToSquared(_bonePos)   // ← 找最近的骨骼
    if (dist < closestDist) { closestDist = dist; closestRegion = region }
  }
  return closestRegion
}
```
→ **腰部 = `hips` → `buttocks` 区域**，正好是我们想要的抓取点判定。

### ④ OpenPetsHQ/openpets —— 「转发事件会静默失效」的看门狗，我们必抄

- 链接：https://github.com/OpenPetsHQ/openpets

```js
  setInteractiveHit(Boolean(target));

  dragging = true;                                    // ← mousedown 即抓，无起始阈值

  dragging = false;
```

**看门狗（Windows 上必踩的坑，原文注释极有价值）**【自查，`mouse-forwarding.ts`】：
```ts
/**
 * Forwarded mouse events are the *only* way a click-through pet learns that the
 * cursor is over it, and the compositor can silently stop delivering them:
 *   - Windows: Chromium's forwarded mouse tracking goes stale after rapid pet
 *     HTML reloads and fullscreen sweeps.
 *   - macOS: the WindowServer stops delivering forwarded moves after Space
 *     switches, display sleep, and fullscreen transitions.
 * When that happens the renderer's hit-test never fires, passthrough is never
 * lifted, and the pet becomes permanently unclickable and undraggable until the
 * app restarts. The watchdog re-arms forwarding from the main process using
 * `screen.getCursorScreenPoint()`, which keeps working even when event
 * forwarding is dead.
 */
```
主进程侧每 **750ms** 探针 + 重新武装，并在 reload 后 250/500/1000/1500ms 四连补【自查，`pet-window.ts:478-566`】。

> **可借鉴点**：这正是我们"QtWebEngine 收不到常规鼠标事件"的同类问题。他们的答案：**不要只依赖转发事件，用主进程/宿主侧的全局坐标轮询做权威来源**（Qt 侧对应 `QCursor.pos()` + `QTimer`）。以及"按下即抓、抬起回退为点击"的判定顺序。

```ts
function onCanvasPointerDown(event: PointerEvent) {
  if (!event.isPrimary || event.button !== 0) return
  activePointer = { id: event.pointerId, x: event.clientX, y: event.clientY }
}
function onCanvasPointerUp(event: PointerEvent) {
  const pointer = activePointer; activePointer = undefined
  if (!pointer || pointer.id !== event.pointerId || !event.isPrimary) return
  if (!isClickLikePointerGesture(pointer, { x: event.clientX, y: event.clientY })) return  // >8px 直接放弃拾取
  handleCanvasInteraction(event)
}
```
真相不是"区分两种拖拽目标"，而是 **≤8px 判为点击角色，>8px 直接 `return` 放弃拾取**，而**绑在同一 DOM 元素上的原生 three `OrbitControls` 已按左键把相机转了**。二者共享 `renderer.domElement`，无 `stopPropagation`、无 `pointer-events` 切换：
```ts
controls.value = new OrbitControls(camera.value, renderer.domElement)
controls.value.enablePan = false; controls.value.enableZoom = false; controls.value.enableRotate = false
controls.value.mouseButtons = { LEFT: MOUSE.ROTATE, MIDDLE: MOUSE.DOLLY, RIGHT: MOUSE.PAN }
```
**→ 让 OrbitControls 天然吃掉"大位移"，自己只处理"小位移点击"**，无需手写拖拽状态机，也不会与相机操作打架。

**拾取调用链（已补全）**：`ThreeScene.vue:589-599` → `pickingRaycaster.setFromCamera(...)` → `intersectObjects([...activeColliders])`，**只取 `intersects[0]`（最近）且非递归**（未传 `true`），再把 `vrm_interaction_*` 名字前缀反解成部位枚举。

**像素 alpha（穿透判定）**：VRM/three 路径走**离屏 RenderTarget**（`stage-ui-three/.../render-target.ts`：`setRenderTarget` → `clear` → `render` → `readRenderTargetPixels`），**阈值默认 10**——与 claw-sama 是同一套方案。另有 `stage-ui/src/composables/canvas-alpha.ts` 的 `gl.readPixels` **直读主缓冲**变体，那是 **Live2D/贴图（tachie）路径**，不是 VRM 路径。两者都加了**半径 25px 圆形采样**消除边缘抖动。

**重复触发节流：450ms / 部位**（Map 以部位为 key，分别计时）：
```ts
const VRM_INTERACTION_COOLDOWN_MS = 450
function onVRMInteract(target: VrmInteractionTarget) {
  const now = Date.now()
  const lastTriggeredAt = lastVrmInteractionAt.get(target) ?? 0
  if (now - lastTriggeredAt < VRM_INTERACTION_COOLDOWN_MS) return
  lastVrmInteractionAt.set(target, now)
  vrmViewerRef.value?.setExpression(getVrmInteractionExpression(target), 1)
}
```
部位→表情：head→`happy`，脚→`relaxed`，其余→`surprised`。

**airi 的角色位置由滑块驱动，与鼠标拖拽无关**【子代理】：`applyModelTransform()` 只读 Pinia 里的 `modelOffset` / `modelRotationY`，**没有任何把鼠标 drag 位移映射到 `modelOffset` 的代码**；VRM 的 OrbitControls **未开 `enableDamping`**（即刻跟手、无惯性）。`springBoneManager.update(delta)` 外层的 `measureFrameStep` 纯属性能埋点，**不代表任何拖拽驱动**。拖窗用 `electron-click-drag-plugin`（`window.getNativeWindowHandle()` → `startDrag()`）。

> **可借鉴点**：①「click 用 8px 判定 / 大位移交给 OrbitControls」——**我们 120fps 逐帧轮询下尤其省事**；②包围盒 proxy + 最近命中比真网格射线便宜，适合每帧预筛；③450ms/部位节流 + 圆形采样消抖；④8px 判定抽成纯函数并单测。

## 三、专项问题：吊点 / 惯性 / 回弹 的具体算法

### 3.1 吊点（grab point）模型 —— 开源里只有三种形态

| 形态 | 项目 | 实现 |
|---|---|---|
| **配置化吊点 + 姿态状态机** | VPet | `Point[] RaisePoint`（四态各一）+ `Raised_Dynamic/Static` 四阶段 |
| **锚点偏移** | Shimeji | `setAnchor(cursor.x, cursor.y+120)` —— 吊点与身体分离 |
| **物理约束（软吊点）** | cannon-es / Rapier / Unity | `PointToPointConstraint` / `JointData.rope()` / `SpringJoint` |

**物理软吊点的标准范式**【子代理】：射线命中点 → 换算成刚体局部 pivot → 建 `mass=0` 的代理刚体当"手"（且 `collisionFilterGroup=0, collisionFilterMask=0` 不参与碰撞）→ 点到点约束。
- cannon-es 官方 mousepick 用 `maxForce=1e6`（**等于钳子，硬到像夹子**）
- **要"提线木偶感"必须软化**：Rapier 的 `JointData.rope(length, a1, a2)`（绳只抗拉不抗压，对应 `JointType.Rope=3`）最贴切；用 spring 会得到"被棍子戳"的怪感
- Unity 标准做法是 **SpringJoint 而非 FixedJoint**：`spring=50, damper=5, maxDistance=0.2`
- Godot **没有 `DampedSpringJoint3D`**（只有 2D 版），3D 只能用 `PinJoint3D`(bias=0.3, damping=1.0) 或 `Generic6DOFJoint3D`

### 3.2 惯性摆动：three-vrm springBone 的真实公式（我核对了原文）

`packages/three-vrm-springbone/src/VRMSpringBoneJoint.ts` 的 `update()`【自查】：
```ts
// verlet 积分计算下一个位置
_nextTail
  // 在 center 空间内确定惯性
  .copy(this._currentTail)
  .add(_v3A.subVectors(this._currentTail, this._prevTail)
        .multiplyScalar(1 - this.settings.dragForce))   // 延续上一帧的移动（带衰减）
  .applyMatrix4(this._getMatrixCenterToWorld())          // tail 回到 world 空间
  // 在世界空间施加强度与重力
  .addScaledVector(worldSpaceBoneAxis, this.settings.stiffness * delta)   // 父骨旋转带来的目标位移
  .addScaledVector(this.settings.gravityDir, this.settings.gravityPower * delta)  // 外力位移

// 归一化骨骼长度
_worldSpacePosition.setFromMatrixPosition(this.bone.matrixWorld);
_nextTail.sub(_worldSpacePosition).normalize().multiplyScalar(this._worldSpaceBoneLength).add(_worldSpacePosition);
this._collision(_nextTail);   // 碰撞
this._prevTail.copy(this._currentTail);
this._currentTail.copy(_nextTail).applyMatrix4(this._getMatrixWorldToCenter());
```
即 **`nextTail = currentTail + (currentTail − prevTail)×(1−dragForce) + stiffness×dt×boneAxis + gravityDir×gravityPower×dt`**，再保长。

**参数默认值与含义**【自查 + 子代理】：
```text
stiffness      回正刚度，three-vrm 默认 1.0；头发 0.3~0.8，裙摆 0.5~1.0
dragForce      [0,1] 逐帧动量保留系数 (1−drag)，默认 0.4
               0.05~0.15 → 长余韵明显摆动；0.4 → 明显收敛；0.7+ → 几乎僵直
gravityPower   默认 0.0；VRM JSON 示例 1.0；头发 0.1~0.5
gravityDir     默认 (0,-1,0)
hitRadius      默认 0.0（米）
```

**⚠️ center space 是关键（VRM 1.0 特性）**【子代理，vrm-spec】：`center` 指定祖先节点（如骨盆），**惯性在该节点局部空间计算，重力仍在世界空间**。不设 center 时，搬动人形会让全身 springBone 在拖动瞬间**集体甩飞**。对我们这种"抓腰拖动"的场景，**必须设 `center = hips`**。

### 3.3 松手回弹/余韵 —— 三种做法

1. **速度继承（最廉价、最像活物）**：松手帧读 `linearVelocity/angularVelocity`（或 Shimeji 那样用鼠标速度 EMA）作为初速度。**不给速度就"立刻定格"，这是廉价感的主要来源。**
2. **阻尼弹簧回正**：即 §3.2，欠阻尼二阶系统 `ω_n = √(k/m)`，`ζ = c/(2√(km))`。经验：**ζ≈0.3 → 过冲约 37%；ζ≈0.5 → 约 16%；ζ≥1 → 无过冲**。想要"松手抖两下"取 ζ≈0.2~0.4。
3. **物理↔动画混合权重**：unity-chan `SpringManager.cs` 的 `Quaternion.Lerp(org.rotation, secondaryRotation, dynamicRatio)`——松手时把 `dynamicRatio` 在 0.2~0.4s 内从 1 衰减到 0，物理余韵自然让位给动画。**比"直接开关物理"自然得多。**

**Godot Active-Ragdolls 的模式切换**（比泛泛的 blending 具体）【子代理】：
```gdscript
func trace_skeleton(value : bool) -> void:
    self.set_physics_process(value)
    _declare_flag_for_all_axis(Generic6DOFJoint.FLAG_ENABLE_ANGULAR_LIMIT, not value)  # 追动画→关角限
    _declare_flag_for_all_axis(Generic6DOFJoint.FLAG_ENABLE_MOTOR, value)              # 追动画→开马达
```
→ **抓起时：开角限 + 关马达（瘫软）；追动画时：关角限 + 开马达（僵硬）**。直接对应"被拎起来软、松手回弹"。

**帧率无关阻尼公式（three-vrm 官方 lookat-advanced）**【子代理】——直接可用在拖拽跟随上：
```js
const k = 1.0 - Math.exp( - smoothFactor * delta );   // smoothFactor = 10.0
this._yawDamped += ( this._yaw - this._yawDamped ) * k;
```

## 四、我们环境（QtWebEngine + 全局鼠标轮询）的适配要点

**架构对标**：我们和 claw-sama / GodotDesktopPet 是同一类问题——**窗口要么收不到鼠标事件、要么事件穿透，所以必须用宿主侧全局坐标轮询当权威来源**。Qt 侧对应：

| 需求 | 开源做法 | 我们的落地 |
|---|---|---|
| 全局鼠标位置 | claw-sama Rust `GetCursorPos` 32ms 轮询；Godot `DisplayServer.mouse_get_position()` | `QCursor.pos()` + `QTimer`（建议 ≤16ms 以匹配 120fps）；**必须做物理像素→逻辑像素换算**（claw-sama `/scale_factor`） |
| 事件失效兜底 | openpets 750ms 看门狗 + reload 后 250/500/1000/1500ms 四连补 | Qt 侧轮询是权威源，天然免除此问题；但**页面 reload 后仍要重置拖拽状态** |
| hit-test | 像素 alpha `>10`（claw-sama）；包围盒 proxy（airi）；真网格+最近骨骼（claw-sama） | 见下方推荐 |
| 拖拽期间 | **强制关闭穿透**（GodotDesktopPet `if is_dragging: _set_click_through(false)`） | 铁律，否则丢事件断线 |

**hit-test 三选一（按我们的条件）**：
1. **真网格 Raycaster + 最近骨骼**（claw-sama 手法）→ 能直接判定"打到腰（`hips`/`spine`）"，**我们需要这个**，因为要按部位给不同反应。
2. **不可见包围盒 proxy 挂骨骼**（airi）→ 更便宜，120fps 每帧可跑；腰/腿各挂一个 capsule/box。
3. **像素 alpha 读 1px**（claw-sama `>10`）→ 与渲染完全一致（含描边/半透明），但每帧多一次 render target。

> **建议组合**：用 ② 做每帧廉价命中 + ① 做按下瞬间的部位精判。因为我们是 120fps 全局轮询，每帧都跑真网格射线（`intersectObject(vrm.scene, true)`）在 VRM 高模上代价偏高。

**拖拽 vs 单击/双击 阈值（可直接采用）**：
```text
拖动判定：位移 > 5px（claw-sama）或 > 8px（airi）；Godot 用 12px + 250ms 双条件
点击判定：位移 ≤ 5px 且 时长 ≤ 300ms（claw-sama 双条件，最严谨）
双击：同部位 + 间隔 ≤ 500ms（claw-sama），触发后同部位 5s 冷却
重复触发节流：450ms / 部位（airi，Map 按部位分别计时）
关键设计：mousedown 立即抓（反馈即时）→ mouseup 时回退判定为点击（openpets）
拖动结束后抑制 click 300ms（openpets），避免"松手触发点击"
"真的被拖走"：位移 > 20px（VPet）/ > 30px（Godot）
```

> **⚠️ 对我们的特别建议**：airi 那条「**小位移（≤8px）判点击、大位移直接 `return` 交给相机轨控**」在**逐帧轮询**的架构下比手写完整拖拽状态机更省事、也更不容易与"拖动视角"打架——因为它根本不需要在 `pointermove` 里维护拖拽状态。我们可以照搬：轮询发现位移 >8px 且按在腰上 → 进抓取态；否则让给相机/穿透逻辑。

## 五、最值得抄的 3 个方案（按落地难度排序）

### 🥇 方案一（最容易，纯设计层，建议先做）：VPet 的「吊点 + 四阶段被提起状态机」

**抄什么**：
- `RaisePoint`：按状态/表情分设的抓取点（我们 42 个表情，可按心情给不同吊点）
- 四阶段：`Raised_Dynamic`(×3，提起瞬间的挣扎/悬垂) → `A_Start` → `B_Loop`(持续悬吊，播到松手) → `C_End`(松手过渡)
- 1px 死区防抖 + 20px"真的被拖走"阈值

**为什么最容易**：不依赖任何物理引擎，只改动画层——我们已有的表情/骨骼驱动框架就能承载。

**要改哪些部分**：
1. 在 `vrm.humanoid.getNormalizedBoneNode('hips')` 上建立抓取点状态（我们已经在写 Spring 类，直接扩展成状态机）。
2. 新增 `dragStage` 枚举（Dynamic / StaticStart / StaticLoop / End），由鼠标轮询的"按下/移动/释放"驱动。
3. `B_Loop` 期间**调高 `gravityPower` 并降低 `stiffness`**（见 §3.2 参数），让腿/头发自然下垂——这就是"重量感"的来源，比手写腿摆动自然得多。
4. 松手时进 `C_End`，并在 0.2~0.4s 内把 springBone 权重交还给 idle 动画。

---

### 🥈 方案二（中等，改 1 个类约 30 行）：GodotDesktopPet 的「弹簧力跟随 + 重力缩放」

**抄什么**：`F = k·x − c·v` 的力模型，**不直接赋位置**；拖拽时重力降到 0.1 倍；松手恢复重力且**不清零速度**。

**为什么值得**：这是"治木偶感"的核心机制——直接赋位置 = 木偶；施力让骨骼自己算 = 有生命。参数 `k=80, c=6, gravityScale=0.1` 可直接作为调参起点。

**要改哪些部分**（我们无物理引擎，需用弹簧代替受力积分）：
```js
// 把 Godot 的 apply_central_force 换成对 hips 的速度积分
// F = k*x - c*v  →  a = F/m  →  v += a*dt  →  x += v*dt
const disp = mouseTarget.sub(hipsWorldPos)          // x：鼠标到目标点的位移
const F = disp.multiplyScalar(K).sub(vel.clone().multiplyScalar(C))
vel.addScaledVector(F, dt / MASS)                   // 模拟 dt
hips.position.addScaledVector(vel, dt)              // 只动 hips，其余交给 springBone
```
1. 把 `k=80 / c=6` 按我们模型尺度与 120fps 重新标定（`k=80` 是 Godot 像素单位，VRM 是米制，需要按比例缩放；建议先用 `1 - exp(-s·dt)` 形式保证帧率无关）。
2. **只施加到 `hips`（或 `vrm.scene`）**，不逐骨骼赋位置——让 springBone 自己产生腿/发/裙的滞后摆动。
3. 拖拽期间 `gravityPower` 降低（对应 `DRAG_GRAVITY_SCALE=0.1`），松手恢复。
4. **松手时保留 `vel`**（`vel` 不清零）→ 这就是惯性滑行与回弹的来源。

---

### 🥉 方案三（最难，但效果最像活物）：claw-sama 部位 hit-test + springBone center + 松手速度继承

**抄什么**：
- claw-sama 的 **真网格 Raycaster + 最近骨骼** 部位判定（`hips→buttocks` 即"腰"）
- claw-sama 的**全局轮询 + 物理→逻辑像素换算**（32ms，我们可提到 8ms 配 120fps）
- 阈值体系 5px / 300ms / 双击 500ms / 冷却 5s
- **§3.3 的速度继承**（Shimeji 的 `InitialVX=cursor.dx` 思路）+ **§3.2 的 `center=hips`**
- 可选：Live2D `L2DTargetPoint` 的**加速度限幅 + 速度上限**积分器，替代简单 lerp，天然产生过冲回稳

**为什么最难**：涉及渲染管线（射线/读像素）、物理空间（center space）、以及松手瞬间的速度采集三处改动，且参数需要实测调优。

**要改哪些部分**：
1. **hit-test**：加 `THREE.Raycaster` + `boneRegionMap`，按下时判定是否命中 `hips/spine` 区域；每帧轮询用廉价包围盒 proxy 预筛。
2. **让位移真正进入 3D 世界**：不再只搬 Qt 窗口，而是移动 `vrm.scene.position`（或 `hips`）。**这是与所有现有项目最根本的区别，也是头发能甩动的前提。**
3. **springBone center**：`vrm.springBoneManager` 里给相关 joint 设 `center = hips`，否则拖动瞬间全身 springBone 集体甩飞。
4. **松手速度继承**：在释放帧采集当前 `vel`（方案二的积分速度）与上一帧鼠标速度 EMA，作为释放初速度。
5. **回弹参数**：目标 `ζ≈0.2~0.4`（松手抖两下）；`dragForce` 拖拽中降到 0.05~0.15（长余韵），松手后回到 0.4。
6. **兜底**：拖拽期间强制关闭任何穿透/忽略鼠标状态；页面 reload 后重置拖拽状态机。
